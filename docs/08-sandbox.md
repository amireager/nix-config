# ۰۸ — سندباکس: موتور جامع `box` و ابزار ممیزی `audit`

دو ابزار، دو کار متضاد و عمداً جدا:

| ابزار | کار | زمان |
| :--- | :--- | :--- |
| `box` | «این را اجرا کن، ولی نگذار به سیستمم دست بزند» | حین اجرا |
| `audit` | «این چیز سالم است؟ سیستم من سالم است؟» | ایستا، فقط خواندن |

هر دو خودنوشته‌اند و بزرگ‌ترین قابلیت‌های امنیتی این مخزن هستند.

---

## چرا `box` ساخته شد؟

سه مسئله‌ی حیاتی که یک مکانیزم هر سه را حل می‌کند:

**۱. امنیت و حفاظت از کلیدها (Zero-Trust):** یک پکیج npm یا یک agent که سورسش را نخوانده‌اید، نمی‌تواند `~/.ssh` و `~/.aws` و توکن‌های شما را بخواند. آنها درون سندباکس وجود ندارند (`ENOENT`).

**۲. تمیزی سیستم و ایزولاسیون محلی:** پکیج‌های نصب‌شده با `npm -g`, `pip`, `cargo` و `curl | bash` درون پوشه `.box/home/` همان پروژه ذخیره می‌شوند و سیستم اصلی را دست‌نخورده باقی می‌گذارند.

**۳. معماری Home-Swap روی مسیر واقعی کاربر (`/home/amir`):**
در سندباکس‌های سنتی اگر نام کاربر به `dev` تغییر کند، تمام اسکریپت‌های پایتون با خطای خراب شدن Shebang (`#!/home/amir/.../.venv/bin/python`) مواجه می‌شوند. موتور `box` یک لایه ایزوله محلی (`.box/home`) را مستقیماً روی همان مسیر `$REAL_HOST_HOME` جابجا (Swap) می‌کند؛ در نتیجه تمامی ابزارها و Shebangها ۱۰۰٪ بدون خطا کار می‌کنند.

## ساختار و دستورات `box`

رابط کاربری `box` کاملاً یکپارچه و بر پایه فلگ‌هاست:

```sh
box [FLAGS] [COMMAND [ARGS...]]
```

### حالت‌های پرکاربرد:

| دستور / فلگ | عملکرد | توضیح |
| :--- | :--- | :--- |
| `box` | ورود به شل تعاملی (Fish) | شل ایزوله در پوشه `/work` با خانه ایزوله |
| `box python app.py` | اجرای مستقیم در سندباکس | ایزولاسیون کامل با حفظ قابلیت وب‌سرور/پورت‌ها |
| `box -e <cmd>` | **حالت موقت (RAM / Ephemeral)** | استفاده از tmpfs؛ پس از خروج هیچ فایلی روی دیسک نمی‌ماند |
| `box -n <cmd>` | **قطع کامل شبکه (Zero-Net)** | تست کدهای مشکوک بدون کوچک‌ترین دسترسی به اینترنت |
| `box -g <cmd>` | **شتاب‌دهنده کارت گرافیک (GPU)** | پاس دادن Nvidia GTX 1650 و درایورهای CUDA به سندباکس |
| `box -P 1819 <cmd>` | **پروکسی اجباری** | هدایت خودکار تمام ترافیک وب به پورت پروکسی محلی |
| `box -s <SRC>[:<DST>]` | **اشتراک فقط خواندنی (RO)** | مانت امن مسیر بدون دستکاری (مثلاً `-s ~/.config/nvim`) |
| `box -S <SRC>[:<DST>]` | **اشتراک خواندنی و نوشتنی (RW)** | مانت مسیر برای نوشتن داده (مثلاً `-S ~/Downloads`) |
| `box -w <DIR>` | **فضای کاری سفارشی** | تعیین دایرکتوری دلخواه به عنوان `/work` |
| `box --mem 4G` | **محدودیت سقف رم** | اعمال محدودیت cgroups رم برای جلوگیری از فریز سیستم |
| `box --cpu 200%` | **محدودیت پردازنده** | محدود کردن سهم CPU |
| `box --clean` | **پاک‌سازی داده‌ها** | حذف کامل پوشه محلی `.box` در پروژه جاری |
| `box --inspect <cmd>` | **ردگیری با strace** | مانیتورینگ دسترسی‌های سیستمی و فایل‌ها |

### ساختار خودکار `.box/`:
* **`.box/home/`:** نگهداری فایل‌های پیکربندی و کش‌های پکیج‌ها به صورت محلی.
* **`.box/tmp/`:** نگهداری پوشه `/tmp` برای بقای فایل‌های موقت در حالت عادی.
* **`.box/<name>`:** هر پوشه سفارشی که در `.box/` بسازید، به طور خودکار به صورت `/<name>` داخل سندباکس مانت می‌شود.

## ابزار ممیزی و اسکن امنیتی (`audit`)

شل `dev audit` بسته‌ای از ابزارهای بازرسی بدون اجرای کد است:

```sh
dev audit
```

* **`audit-all`:** اجرای کامل بازرسی با یک کلیک (اسکن سکرت‌های گیت + آسیب‌پذیری قفل‌فایل‌ها + اسکن CVE سیستم).
* **`audit-repo`:** اسکن نشت کلیدها با `gitleaks` و آسیب‌پذیری پکیج‌ها با `osv-scanner`.
* **`audit-system`:** ممیزی بسته‌های فعال سیستم‌عامل با `vulnix` برای شناسایی CVEهای ثبت‌شده.
* **`lynis audit system`:** امتیازدهی به امنیت و سخت‌سازی پیکربندی لینوکس.
