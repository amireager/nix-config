# ۰۸ — سندباکس: `box` و `audit`

دو شل، دو کار متضاد و عمداً جدا:

| | کار | زمان |
| :--- | :--- | :--- |
| `box` | «این را اجرا کن، ولی نگذار به سیستمم دست بزند» | حین اجرا |
| `audit` | «این چیز سالم است؟ سیستم من سالم است؟» | ایستا، فقط خواندن |

هر دو خودنوشته‌اند و بزرگ‌ترین چیزی‌اند که در این مخزن ساخته شده.

---

## چرا `box` ساخته شد

سه مسئله‌ی جدا که یک مکانیزم هر سه را حل می‌کند:

**۱. امنیت.** یک پکیج npm یا یک agent که سورسش را نخوانده‌ای، `~/.ssh` و
`~/.aws` و توکن‌هایت را می‌خواند.

**۲. تمیزی.** agentها config و cache و state را در سراسر home پخش می‌کنند.

**۳. هویت.** هر agent باید home خودش را داشته باشد. این یکی نظری نیست —
در عمل دیده شد که `mimo` سراغ `~/.local/share/opencode/auth.json` و
`~/.claude/projects` می‌رود. یعنی یک agent، کلید agent دیگر را می‌خواند.

---

## تفاوت بنیادی با روش متغیر محیطی

راه ساده این است که `XDG_CONFIG_HOME` را عوض کنی. کار نمی‌کند:

```
با env var  →  ابزار همچنان می‌تواند $HOME را بخواند و هرجا بنویسد
با box      →  syscall برمی‌گردد ENOENT، چون چیزی برای باز کردن نیست
```

`box` یک **mount namespace** می‌سازد که مسیرهای اجازه‌داده‌نشده در آن
**اصلاً وجود ندارند**. تفاوت «اجازه ندارد بخواند» با «چیزی نیست که بخواند».

### ترفند جابه‌جایی home

پوشه‌ی profile روی **مسیر واقعی home** بایند می‌شود، نه اینکه فقط `$HOME` به
آن اشاره کند:

```sh
--tmpfs  /home/$USER          # اول خالی اش کن
--bind   .box/profiles/x  /home/$USER
```

دلیلش این است که خیلی از ابزارها متغیر محیطی را نادیده می‌گیرند و
`getpwuid(getuid())->pw_dir` صدا می‌زنند. mount روی مسیر واقعی هر دو راه را
می‌بندد. داخل box مسیر `/home/$USER` وجود دارد و قابل نوشتن است — ولی
محتوایش profile است و home واقعی اصلاً در namespace نیست.

## دو سطح سخت‌گیری، و چرا دوتاست

```sh
box run <cmd>     allowlist: فقط /nix/store و چند فایل /etc
box dev <cmd>     کل سیستم read-only، فقط home عوض شده
```

`box run` سخت‌گیرترین است، ولی اسکریپت‌های `#!/bin/bash` و باینری‌های دانلودی
در آن **کار نمی‌کنند** — چون `/bin` و `/run/current-system` وجود ندارند.

`box dev` کل سیستم را read-only می‌دهد. اسکریپت‌ها و باینری‌های از پیش
ساخته‌شده کار می‌کنند (`nix-ld` هم رد می‌شود)، سیستم قابل تغییر نیست، و home
واقعی همچنان نامرئی است. **این جایگزین `fj` قدیمی است و حالت معمول کار.**

| زیردستور | شبکه | سیستم | کاربرد |
| :--- | :--- | :--- | :--- |
| `box dev` | ✔ | read-only | حالت معمول |
| `box run` | ✔ | فقط store | سخت‌گیرانه |
| `box net` | ✖ | read-only | مثل dev، بدون شبکه |
| `box exec` | ✔ | read-only | غیرتعاملی، با `--new-session` |
| `box vm` | ✔ | podman | kernel جدا |

---

## بقیه‌ی زیردستورها

```sh
box shell                  یک شل داخل box، برای گشتن
box inspect <cmd>          strace: این ابزار واقعاً چه مسیرهایی می خواهد
box limit <cmd>            سقف رم و CPU  (systemd-run)
box ls                     فهرست profileها
box -p work dev <cmd>      profile نام دار
box -p work clean          پاک کردن یک profile
```

`-p` قبل یا بعد از زیردستور هر دو قبول است، چون هر دو طبیعی خوانده می‌شوند.

`box inspect` مدرک می‌دهد به‌جای حدس: با `strace` می‌گوید ابزار سراغ چه
مسیرهایی بیرون از پروژه رفته.

---

## محیط داخل box

عمداً حداقلی است. **نه `SSH_AUTH_SOCK`، نه کلید API، نه GPG agent.** اگر
ابزاری به یک راز نیاز دارد، باید صریحاً داخل profile گذاشته شود.

profileها اینجا زندگی می‌کنند و per-project هستند:

```
<project>/.box/profiles/<name>/
```

یک `.gitignore` با محتوای `*` خودکار در `.box/` ساخته می‌شود.

---

## نکته‌ی `--new-session` — یک تصمیم با هزینه

`bwrap --new-session` تابع `setsid()` صدا می‌زند و sandbox را از ترمینال
کنترلی جدا می‌کند. این جلوی حمله‌ی تزریق کلید `TIOCSTI` را می‌گیرد.

ولی هر TUI تعاملی را هم می‌شکند: fish بالا نمی‌آید («No TTY for interactive
shell») و رابط چت agentها اصلاً رسم نمی‌شود.

پس برای حالت تعاملی حذف شده و به‌جایش به کرنل تکیه می‌کنیم — `TIOCSTI` از
لینوکس ۶.۲ به بعد پیش‌فرض خاموش است:

```sh
sysctl dev.tty.legacy_tiocsti      # باید 0 باشد
```

و در `modules/nixos/security.nix` صریحاً پین شده. فراخوانی‌های غیرتعاملی
(`box exec`) همچنان `--new-session` می‌گیرند، چون چیزی به ترمینال نیاز ندارد.

---

## ⚠️ محدودیت صادقانه

`bwrap` **کرنل را با میزبان شریک است**.

ابزار درست برای «نرم‌افزاری که سورسش را نخوانده‌ام» و «جلوی این را بگیر که
home‌ام را کثیف کند». **مرزی در برابر بدافزار عمدی نیست** — یک اکسپلویت کرنل
از آن فرار می‌کند. برای آن `box vm` هست که با podman یک root و سطح کرنل
جدا می‌دهد.

## `audit` — بازرسی چیزی که همین حالا داری

مکمل `box` و عمداً فعالیت متضاد. **هیچ‌چیز اینجا کد نامعتبر اجرا نمی‌کند** —
هر ابزار می‌خواند و گزارش می‌دهد.

```sh
dev audit

audit-system      CVEهای closure سیستم + permittedInsecurePackages کهنه
audit-repo        رازها در تاریخچه ی گیت + آسیب پذیری در lockfileها
```

این دو اسکریپت نوشته شده‌اند چون فراخوانی مفیدشان طولانی و فراموش‌شدنی است:

| اسکریپت | زیرش چه اجرا می‌شود |
| :--- | :--- |
| `audit-system` | `vulnix --system` + گرفتن `permittedInsecurePackages` |
| `audit-repo` | `gitleaks detect` + `osv-scanner scan source -r` |

ابزارهای دیگر داخل شل:

| ابزار | کار |
| :--- | :--- |
| `lynis audit system` | نمره‌ی سخت‌سازی این ماشین (sudo می‌خواهد) |
| `trivy image <ref>` | کانتینرها |
| `trivy config .` | Terraform، Kubernetes، Dockerfile |
| `dive <ref>` | ایمیج، لایه به لایه |
| `syft dir:. -o json \| grype` | SBOM بساز و اسکن کن |
| `trufflehog filesystem .` | آیا کلیدِ پیداشده هنوز زنده است |
| `cosign` / `age` / `sops` | امضا و رمزگذاری |

### چرا `checkov` عمداً نیست

به `python-ecdsa` وابسته است که nixpkgs آن را برای CVE-2024-23342 (حمله‌ی
زمانی Minerva روی P-256) ناامن علامت زده. upstream حملات کانال جانبی را خارج
از دامنه می‌داند و گفته برنامه‌ای برای رفع ندارد.

یعنی یک ورودی `permittedInsecurePackages` **دائمی** لازم می‌شد — دقیقاً همان
نوع استثنای کهنه‌ای که `audit-system` ساخته شده تا پیدایش کند. `trivy config`
همان پوشش را می‌دهد.

---

## چه چیزی جایگزین چه چیزی شد

شل `sec` قدیمی حذف شد. `bubblewrap` و `firejail` داشت که هر دو کار
سطح-سیستم `firejail`/`fj` را تکرار می‌کردند و `box` از آن‌ها بهتر بود. اسم
`audit` برای کاری آزاد شد که خانه نداشت: **بررسی کردن**.

مخفف‌های `fj` و `fjx` هنوز در fish هستند برای کارهای سریع، ولی حالت اصلی
`box dev` است.
