# ۰۸ — سندباکس: موتور جامع `box` و ابزار ممیزی `audit`

دو ابزار، دو کار متضاد و عمداً جدا:

| ابزار | کار | زمان |
| :--- | :--- | :--- |
| `box` | «این را اجرا کن، ولی نگذار به سیستمم دست بزند» | حین اجرا |
| `audit` | «این چیز سالم است؟ سیستم من سالم است؟» | ایستا، فقط خواندن |

هر دو خودنوشته‌اند و بزرگ‌ترین قابلیت‌های امنیتی این مخزن هستند.

`box` یک devShell نیست؛ مانند فرمان `dev` در سطح Home Manager نصب می‌شود تا همیشه در دسترس باشد و هنگام اجرا PATH و ابزارهای محیط فراخواننده را به ارث ببرد. کد، بسته‌بندی و completionهای آن در `modules/home/dev/box/` نگهداری می‌شوند.

---

## چرا `box` ساخته شد؟

سه مسئله‌ی حیاتی که یک مکانیزم هر سه را حل می‌کند:

**۱. امنیت فایل‌ها و کلیدها:** Home-Swap فایل‌هایی مانند `~/.ssh`، `~/.aws` و فایل‌های احراز هویت را از دید پردازش داخل Box خارج می‌کند (`ENOENT`). حالت استاندارد برای حفظ ابزارهای محیط، متغیرهای میزبان را به ارث می‌برد؛ برای کد واقعاً نامطمئن باید `--secure` استفاده شود تا environment نیز پاک شود و فقط متغیرهای لازم با `--env-pass` برگردند.

**۲. تمیزی سیستم و ایزولاسیون محلی:** پکیج‌های نصب‌شده با `npm -g`, `pip`, `cargo` و `curl | bash` درون پوشه `.box/home/` همان پروژه ذخیره می‌شوند و سیستم اصلی را دست‌نخورده باقی می‌گذارند.

**۳. معماری Home-Swap روی مسیر واقعی کاربر (`/home/amir`):**
در سندباکس‌های سنتی اگر نام کاربر به `dev` تغییر کند، تمام اسکریپت‌های پایتون با خطای خراب شدن Shebang (`#!/home/amir/.../.venv/bin/python`) مواجه می‌شوند. موتور `box` یک لایه ایزوله محلی (`.box/home`) را مستقیماً روی همان مسیر `$REAL_HOST_HOME` جابجا (Swap) می‌کند؛ در نتیجه تمامی ابزارها و Shebangها ۱۰۰٪ بدون خطا کار می‌کنند.

## ساختار و دستورات `box`

رابط کاربری `box` کاملاً یکپارچه و بر پایه فلگ‌هاست:

```sh
box [FLAGS] [COMMAND [ARGS...]]
```

### حالت‌های پرکاربرد:

| دستور / فلگ | عملکرد | توضیح |
| :--- | :--- | :--- |
| `box` | ورود به شل تعاملی | فضای کاری مستقل `.box/work → /work` و خانه‌ی ایزوله |
| `box <cmd>` | اجرای مستقیم | فرمان را با ابزارها و PATH محیط فراخواننده اجرا می‌کند |
| `box --dry-run <cmd>` | **پیش‌نمایش** | Plan کامل را بدون ساخت فایل یا اجرای process نشان می‌دهد |
| `box --secure <cmd>` | **حالت سخت‌گیرانه** | environment پاک و عدم نمایش عمومی `/run` و `/var`؛ شبکه همچنان فعال است |
| `box -e <cmd>` | **حالت موقت** | Home، `/tmp` و `/work` همگی tmpfs هستند |
| `box --net none <cmd>` | **قطع شبکه** | معادل `-n` و `--offline` |
| `box --net proxy:1819 <cmd>` | **Proxy environment** | تنظیم متغیرهای SOCKS5 بدون ادعای جلوگیری از bypass |
| `box -g <cmd>` | **GPU** | پاس دادن deviceهای NVIDIA و در حالت secure فقط driverهای ضروری |
| `box -s <SRC>[:<DST>]` | **اشتراک فقط‌خواندنی** | مانت صریح مسیر میزبان به sandbox |
| `box -S <SRC>[:<DST>]` | **اشتراک خواندنی‌ـ‌نوشتنی** | مانت صریح مسیر قابل نوشتن |
| `box --clear-env` | **محیط پاک** | حذف متغیرهای inherited و نگه‌داشتن defaultهای Box |
| `box --env / --env-pass` | **متغیر صریح** | تنظیم `KEY=VALUE` یا عبور یک متغیر میزبان |
| `box --profile <NAME>` | **Profile مورد اعتماد** | خواندن optionها از تنظیمات شخصی کاربر |
| `box --path / --status` | **مدیریت storage** | نمایش مسیر و حجم `.box` بدون تغییر آن |
| `box --mem 4G / --cpu 200%` | **محدودیت منابع** | استفاده از systemd user scope |
| `box --clean` | **پاک‌سازی** | حذف کامل `.box` با تأیید کاربر |
| `box --inspect <cmd>` | **ردگیری** | مانیتورینگ دسترسی‌های فایل با strace |

### ساختار خودکار `.box/`:
* **`.box/home/`:** نگهداری فایل‌های پیکربندی و کش‌های پکیج‌ها به صورت محلی.
* **`.box/work/`:** تنها فضای کاری پیش‌فرض؛ پوشه‌ای که `box` از آن فراخوانی شده هرگز خودکار mount نمی‌شود.
* **`.box/tmp/`:** نگهداری پوشه `/tmp` برای بقای فایل‌های موقت در حالت عادی.
* **`.box/<name>`:** هر پوشه سفارشی که در `.box/` بسازید، به طور خودکار به صورت `/<name>` داخل سندباکس مانت می‌شود.

در حالت `-e`، `/work` نیز tmpfs است. فقط `-w` می‌تواند یک مسیر میزبان دیگر را به‌صورت صریح به `/work` متصل کند.

### Profileهای مورد اعتماد

هر profile در `~/.config/box/profiles/<name>.conf` قرار می‌گیرد و هر خط دقیقاً یک آرگومان است؛ هیچ shell codeای source یا اجرا نمی‌شود:

```text
# ~/.config/box/profiles/ai.conf
--secure
--gpu
--net
host
--mem
8G
--env-pass
NIX_LD
```

```sh
box --profiles
box --profile ai --dry-run llama-cli
```

## ابزار ممیزی و اسکن امنیتی (`audit`)

شل `dev audit` بسته‌ای از ابزارهای بازرسی بدون اجرای کد است:

```sh
dev audit
```

* **`audit-all`:** اجرای کامل بازرسی با یک کلیک (اسکن سکرت‌های گیت + آسیب‌پذیری قفل‌فایل‌ها + اسکن CVE سیستم).
* **`audit-repo`:** اسکن نشت کلیدها با `gitleaks` و آسیب‌پذیری پکیج‌ها با `osv-scanner`.
* **`audit-system`:** ممیزی بسته‌های فعال سیستم‌عامل با `vulnix` برای شناسایی CVEهای ثبت‌شده.
* **`lynis audit system`:** امتیازدهی به امنیت و سخت‌سازی پیکربندی لینوکس.
