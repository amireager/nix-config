# ۱۰ — تصمیم‌ها

بقیه‌ی صفحه‌ها می‌گویند سیستم **چه کار می‌کند**. این یکی می‌گوید **چرا این
شکلی شد و نه شکل دیگر**.

بدون این ثبت، شش ماه بعد کسی — احتمالاً خودمان — همان راهی را دوباره می‌رود
که یک بار رفتیم و به بن‌بست خورد.

هر ورودی: چه تصمیمی، چه امتحان شد، چه اندازه‌گیری شد، چه درسی ماند.

---

## تکمیل خودکار AI حذف شد — بعد از اینکه کار کرد

**وضعیت:** `minuet` نصب بود و پیشنهاد می‌داد. حذف شد.

**مسئله:** کار کردن کافی نبود؛ هزینه‌اش از ارزشش بیشتر بود.

```
chat : system 400 + few-shots 300 + مقدمه ی gateway 1800 = ۲۵۰۷ توکن
FIM  : prompt + suffix                                    = ~۵۰ توکن
```

۲۵۰۷ توکن برای کامل کردن `local x = `.

**راه‌حل امتحان‌شده:** حالت FIM (fill-in-the-middle) که همان کار را با ۵۰
توکن می‌کند. جواب درستی بود — **برای کسی که gateway‌اش مدل FIM سرو کند**.

**چرا شکست خورد:** `9router` به هر provider که ظرفیت دارد مسیر می‌دهد. و یک
مدل chat پشت endpoint فیم، `200` با بدنه‌ی **خالی** برمی‌گرداند:

```
نه خطا · نه پیشنهاد · نه چیزی برای دیباگ
```

این حالت شکست از نبودن قابلیت بدتر است.

**نکته‌ی زیربنایی:** تکمیل خودکار روی **هر مکث** درخواست می‌فرستد. روی این
خط اینترنت، مکثی که منتظر شبکه بماند یک پیشنهاد کند نیست — یک قفل‌شدگی است
که شبیه خراب بودن nvim به نظر می‌رسد.

**درس:** `<leader>aa` قبلاً وجود داشت تا قابلیت را خاموش کند لحظه‌ای که
تونل می‌افتد. **قابلیتی که با کلید خاموشی خودش می‌آید، دارد چیزی می‌گوید.**

## `command-not-found` سه بار «حل» شد تا واقعاً حل شود

**وضعیت:** غلط تایپی در شل، چند ثانیه مکث می‌کرد و دنبال پکیج می‌گشت.

**تلاش اول:** `programs.nix-index.enableFishIntegration = false`
→ جواب نداد.

**تلاش دوم:** `programs.command-not-found.enable = false` هم اضافه شد
→ باز جواب نداد.

**چرا:** فیش handler را با یک زنجیره‌ی `else if` می‌سازد:

```fish
else if test -f /run/current-system/sw/bin/command-not-found
else if type -q command-not-found        # ← هر چیزی روی PATH
else if type -q pkgfile
```

هر سوییچ **یک شاخه** را برمی‌دارد و فیش می‌افتد روی بعدی. شاخه‌ی
ماقبل‌آخر تله است: هر باینری `command-not-found` که روی PATH باشد — از یک
devShell، یک پروفایل قدیمی، یک generation جامانده.

**هیچ ترکیبی از سوییچ‌ها زنجیره‌ای را نمی‌بندد که fallback آخرش «هر چیزی روی
PATH» است.**

**راه‌حل:** خط اول همان فایل فیش جواب را گفته بود:

```fish
# This can be overridden by defining a new fish_command_not_found function
```

تعریف کردن تابع، کل زنجیره را قبل از اولین probe کوتاه می‌کند.

**اندازه‌گیری** روی fish 4.0.2 واقعی، با یک `command-not-found` که ۲ ثانیه
`sleep` می‌کند:

```
قبل   2.017s   →  lsf: command not found
بعد   0.013s   →  fish: Unknown command: lsf
```

**درس:** پیام خطا نویسنده‌اش را لو می‌دهد. `fish: Unknown command` مال فیش
است؛ `cmd: command not found` مال اسکریپت nix-index. دو رشته‌ی متفاوت یعنی
دو نویسنده‌ی متفاوت — و ما مدت‌ها دومی را می‌دیدیم و فکر می‌کردیم اولی را
درست کرده‌ایم.

## `box` — mount namespace به‌جای متغیر محیطی

**وضعیت:** agentها و ابزارهای نامطمئن به `~/.ssh` و کلیدها دسترسی داشتند.

**راه ساده:** `XDG_CONFIG_HOME` را عوض کن.

**چرا کافی نیست:**

```
با env var  →  ابزار همچنان $HOME را می خواند و هرجا می نویسد
با namespace →  syscall برمی گردد ENOENT — چیزی برای باز کردن نیست
```

تفاوت «اجازه ندارد» با «وجود ندارد».

**جزئیات مهم:** پوشه‌ی profile روی **مسیر واقعی** home بایند می‌شود، نه
اینکه `$HOME` به آن اشاره کند. چون خیلی ابزارها متغیر محیطی را نادیده
می‌گیرند و `getpwuid(getuid())->pw_dir` صدا می‌زنند.

**مشاهده‌ی واقعی که این را ضروری کرد:** یک agent سراغ
`~/.local/share/opencode/auth.json` و `~/.claude/projects` می‌رفت. یعنی بدون
جداسازی، هر agent کلید agent دیگر را می‌خواند.

**درس:** «اجازه ندادن» و «موجود نبودن» دو سطح متفاوت امنیت‌اند.

## `--new-session` حذف شد — یک معاوضه‌ی آگاهانه

**وضعیت:** `bwrap --new-session` جلوی حمله‌ی تزریق کلید `TIOCSTI` را
می‌گیرد.

**مسئله:** `setsid()` صدا می‌زند و sandbox را از ترمینال جدا می‌کند. نتیجه:
fish بالا نمی‌آید («No TTY for interactive shell») و رابط چت agentها اصلاً
رسم نمی‌شود.

**تصمیم:** برای حالت تعاملی حذف شد و به کرنل تکیه شد — `TIOCSTI` از لینوکس
۶.۲ پیش‌فرض خاموش است و در `security.nix` صریحاً پین شده:

```sh
sysctl dev.tty.legacy_tiocsti      # باید ۰ باشد
```

`box exec` (غیرتعاملی) همچنان `--new-session` می‌گیرد چون چیزی به ترمینال
نیاز ندارد.

**درس:** وقتی یک محافظت، قابلیت را می‌شکند، دنبال لایه‌ی دیگری بگرد که همان
را بدهد — و **صریحاً پینش کن** تا به پیش‌فرض تکیه نکنی.

## `mkDevShell` — وقتی ۳۰٪ هر فایل تکرار بود

**وضعیت:** یازده شل، هرکدام همان سه چیز را دستی می‌نوشتند: نام، بنر با ANSI
خام، و `export DEVSHELL_ACTIVE`.

حدود **۳۰٪ هر فایل**، و جعبه‌ی بنر باید هر بار که یک خط متن عوض می‌شد دستی
تراز می‌شد.

**راه‌حل:** سازنده‌ای که *داده* می‌گیرد و بقیه را تولید می‌کند.

**تصمیم مهم — راه فرار:** هیچ اجباری به استفاده از سازنده نیست. یک شل
می‌تواند `pkgs.mkShell` خام باشد و رجیستری اهمیتی نمی‌دهد.

**درس:** انتزاعی که راه فرار ندارد، دیر یا زود سر راه قرار می‌گیرد.

## GC root بعد از خروج ثبت می‌شود، نه هم‌زمان

**وضعیت:** روی **هر** فراخوانی `dev` این چاپ می‌شد:

```
error (ignored): SQLite database '…/eval-cache-v6/….sqlite' is busy
```

**علت:** `nix print-dev-env` در پس‌زمینه هم‌زمان با `nix develop` اجرا
می‌شد و هر دو در یک eval cache می‌نوشتند.

**راه‌حل:** ترتیبی کردن. چون تا آن لحظه ارزیابی cache شده، ثبت ریشه تقریباً
آنی است.

**درس:** «بی‌ضرر است» دلیل نگه داشتن یک خطا در خروجی نیست. چیزی که هر بار
چاپ می‌شود، آموزش می‌دهد که خطاها را نادیده بگیری.

## `dev -w` باید `nativeBuildInputs` بخواند

**وضعیت:** `dev -w <env>` همیشه خالی برمی‌گشت.

**علت:** `buildInputs` را می‌خواند. ولی `mkShell` هرچه در `packages`
بگذاری، در `nativeBuildInputs` می‌گذارد.

**درس:** وقتی خروجی «خالی» است نه «غلط»، معمولاً جای اشتباهی را نگاه
می‌کنی.

## تکمیل خودکار `dev` از فایل می‌خواند، نه از `nix eval`

**تصمیم:** تکمیل، پوشه‌ی `shells/*/` را مستقیم می‌خواند.

**چرا:** اگر از `nix eval` می‌خواند، هر بار زدن TAB یک ارزیابی flake بود.
**۴۳ میلی‌ثانیه** اندازه‌گیری شد.

**درس:** TAB‌ای که دو ثانیه طول بکشد، TAB‌ای است که کسی دوبار نمی‌زندش.

## `show_settings` و `ga` نمی‌توانستند هر دو باشند

**وضعیت:** مستندات گفته بود `ga` مدل را عوض می‌کند. آن کلید اجرا نمی‌شد.

**علت:** خود پلاگین جلویش را می‌گیرد:

```lua
if config.display.chat.show_settings then
  return utils.notify("Adapter can't be changed when
                       `display.chat.show_settings = true`")
end
```

**چرا منطقی است:** با `show_settings` روشن، بلاک بالای بافر *همان* نسخه‌ی
قابل‌ویرایش تنظیمات است. یک picker که همان مقادیر را از سمت دیگر بنویسد،
منبع دومِ حقیقت می‌شد.

**درس:** همان درس «فهرست دوم» — این بار خودِ پلاگین اجبارش می‌کند.

## `checkov` عمداً نصب نیست

**وضعیت:** ابزار اسکن IaC، مفید، ولی به `python-ecdsa` وابسته است که
nixpkgs برای CVE-2024-23342 ناامن علامت زده.

**چرا رد شد:** upstream گفته حملات کانال جانبی خارج از دامنه است و
برنامه‌ای برای رفع ندارد. یعنی یک ورودی `permittedInsecurePackages`
**دائمی** لازم می‌شد.

دقیقاً همان نوع استثنای کهنه‌ای که `audit-system` ساخته شده تا پیدایش کند.

**درس:** ابزاری که برای پیدا کردن مشکل نصب می‌کنی، نباید خودش یکی از همان
مشکل‌ها را اضافه کند. `trivy config` همان پوشش را می‌دهد.

## کلیدهایی که هرگز قابل تایپ نبودند

سه یافته از بازرسی ۲۰۸ کلید:

**`<leader>ft` دو بار bind شده بود** — `snacks.lua` به picker، `ux.lua` به
Trouble. `ux.lua` آخر بار می‌شود، پس بی‌صدا برنده شد و picker غیرقابل‌دسترس
بود. بدون هیچ خطایی، چون `vim.keymap.set` دوم فقط جای اولی را می‌گیرد.

**`<leader>na` هرگز قابل تایپ نبود** — چون `snacks` خودِ `<leader>n` را
دارد، و یک نگاشت تک‌کلیدی **فوراً** اجرا می‌شود. `a` هرگز خوانده نمی‌شد.

**`<leader>fT` دستوری صدا می‌زد که وجود نداشت** — `:TodoTelescope` بدون
telescope.

**درس:** تداخل کلید خطا نمی‌دهد. تنها راه پیدا کردنش شمردن است، و بعد از
آن، `keys.md` از سورس تولید می‌شود تا دوباره پیش نیاید.

## مستندات قبلی دور ریخته شد

**وضعیت:** ۹۵۸ خط مستندات فارسی وجود داشت.

**مسئله:** `git.md` توضیح می‌داد Neogit چیست. `niri.md` توضیح می‌داد
کامپوزیتور scrollable یعنی چه. هر دو مستندات رسمی دارند که بهترند.

در همان حال `shells/box/default.nix` — ۴۲۳ خط، بزرگ‌ترین فایل مخزن — **صفر
خط** مستندات داشت.

**قاعده‌ی جدید:** اگر با `man` پیدا می‌شود، اینجا نیست.

**درس:** مستنداتی که کار upstream را تکرار می‌کند، هم کهنه می‌شود و هم جای
چیزی را می‌گیرد که هیچ‌کس دیگری نمی‌نویسدش.
