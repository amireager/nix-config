# ۰۷ — AI: Gateway، Agent tooling و inference محلی

سه مفهوم در این repository جدا هستند:

| بخش | هدف | owner |
| :--- | :--- | :--- |
| CodeCompanion | کمک تعاملی داخل editor | Neovim + gateway |
| `dev agent` | runtime و ابزار عملیاتی agentهای پروژه | devShell |
| `dev ai` | اجرای model روی GPU/CPU محلی | devShell |

هیچ‌کدام هنگام login، startup Neovim یا ورود به devShell خودکار request، service start یا model download انجام نمی‌دهند.

# جریان درخواست remote AI

```text
Neovim CodeCompanion       project agent / omp
          │                         │
          └────────────┬────────────┘
                       ▼
            http://127.0.0.1:20128/v1
                    9router
                       │
          ┌────────────┼────────────┐
       provider A   provider B   local provider
```

Clientها provider key واقعی ندارند. Gateway routing، rate limit و model availability را مدیریت می‌کند.

Environmentهای متداول:

```text
AI_GATEWAY=http://127.0.0.1:20128
OPENAI_API_BASE=http://127.0.0.1:20128/v1
OPENAI_API_KEY=local
AI_MODEL=<optional override>
```

`local` credential provider نیست؛ فقط clientهایی را راضی می‌کند که empty key را «پیکربندی نشده» می‌دانند.

# مرز secret

نباید در این repository یا Nix store قرار بگیرد:

- OpenAI/Anthropic/Groq token؛
- gateway private config؛
- chat export خصوصی؛
- Bitwarden export؛
- prompt حاوی credential/customer data؛
- model file.

قبل از ارسال Git diff به مدل:

```bash
git diff --cached --check
git diff --cached | rg -n -i \
  'api[_-]?key|token|password|secret|private[_-]?key'
```

این regex secret scanner کامل نیست؛ فقط review اولیه است. `dev audit audit-repo` بررسی عمیق‌تری انجام می‌دهد.

# CodeCompanion داخل Neovim

## رفتار startup

- plugin config load می‌شود؛
- connection باز نمی‌شود؛
- reachability فقط هنگام action بررسی می‌شود؛
- timeout probe کوتاه است؛
- gateway خاموش notification قابل فهم می‌دهد.

## Actionهای اصلی

| کلید | رفتار |
| :--- | :--- |
| `<leader>aa` | chat toggle |
| `<leader>ap` | action palette |
| `<leader>as` | selection به chat |
| `<leader>ai` | inline edit با diff |
| `<leader>ae` | توضیح selection |
| `<leader>af` | پیشنهاد fix |
| `<leader>at` | تولید test |
| `<leader>ad` | توضیح diagnostic |
| `<leader>aC` | پیشنهاد commit message |
| `<leader>ag` | chat با agent tools |
| `<leader>ah` | history |
| `<leader>am` | model picker از gateway |
| `<leader>a?` | status gateway/model |
| `<leader>ax` | تولید Ex command برای review قبل از اجرا |

Inline edit جواب را مستقیم و کورکورانه replace نمی‌کند؛ diff review دارد:

```text
g1  accept all
g2  accept current change
g3  reject current change
```

## Agent tool safety

Chat agent می‌تواند tool مربوط به shell/filesystem داشته باشد، اما action تغییردهنده باید confirmation بگیرد. مدل process trusted نیست؛ prompt injection داخل source/document می‌تواند از tool درخواست نامناسب بسازد.

برای task نامطمئن، Neovim اصلی را agent runtime نکنید؛ command را در Box اجرا کنید.

## history

Chatها auto-save می‌شوند و ۹۰ روز expiration دارند. Title generation یک request اضافه برای chat جدید است، ولی history قابل جست‌وجو می‌سازد.

```vim
:CodeCompanionHistory
```

History secret vault نیست. اطلاعات حساس نباید به chat داده شود.

# `:AIDoctor`

```vim
:AIDoctor
```

این command وضعیت را به failureهای قابل تفکیک تبدیل می‌کند:

1. هیچ listener روی gateway نیست؛
2. gateway پاسخ می‌دهد ولی model list خالی است؛
3. gateway و model آماده‌اند؛
4. endpoint response نامعتبر یا timeout دارد.

بررسی بیرون editor:

```bash
xh --check-status GET http://127.0.0.1:20128/v1/models \
  Authorization:'Bearer local' |
  jq -r '.data[]?.id'
```

اگر `xh` در header syntax نسخه‌ی جاری تفاوت داشت، با `xh --help` همان نسخه تطبیق دهید. Token واقعی در command line ننویسید.

# `dev agent`

این shell agent product خاصی را نصب یا اجرا نمی‌کند؛ runtime و ابزارهایی را می‌دهد که agent project نیاز دارد.

## gateway probe

```bash
dev agent xh GET http://127.0.0.1:20128/v1/models \
  Authorization:'Bearer local'
```

## تحلیل repository قبل از دادن context

```bash
# فقط فایل‌های source مرتبط
dev agent sh -c \
  "rg --files -g '*.nix' -g '*.lua' | rg 'modules|shells'"

# آمار زبان‌ها
dev agent tokei modules shells

# TODOهای واقعی، بدون .git
dev agent rg -n --hidden -g '!.git' 'TODO|FIXME|HACK'
```

## AST به‌جای regex کور

```bash
dev agent ast-grep --lang lua \
  --pattern 'vim.keymap.set($$$ARGS)' modules/home/dev/nvim
```

AST pattern syntax را می‌فهمد و string/comment match تصادفی را کم می‌کند.

## self-correction loop

```bash
dev agent ruff check .
dev agent biome check .
dev agent shellcheck script.sh
dev agent taplo check Cargo.toml
```

`--write` یا `--fix` را فقط بعد از خواندن read-only result اجرا کنید.

## sandbox

```bash
dev agent box --secure --dry-run python agent.py
dev agent box --secure --net none python agent.py
```

اگر agent به source نیاز دارد، share صریح و ترجیحاً read-only بدهید:

```bash
dev agent box --secure -s "$PWD:/source" python /source/agent.py
```

برای نوشتن result، directory کوچک جدا با `-S` بدهید؛ کل repository را read-write share نکنید مگر لازم باشد.

# `dev ai`

این shell runtimeهای محلی را فراهم می‌کند، نه modelها یا service state را.

## health و storage

```bash
dev ai ai-doctor
dev ai ai-storage
```

`ai-doctor` GPU، Vulkan، binaryها و Ollama API را بررسی می‌کند. `ai-storage` directoryهای رایج Ollama/Hugging Face/Whisper را فقط اندازه می‌گیرد.

## Ollama

شروع دستی:

```bash
dev ai ollama serve
```

بررسی از terminal دیگر:

```bash
dev ai ollama list
dev ai curl --fail http://127.0.0.1:11434/api/version
```

Model pull صریح است و ممکن است download بزرگ انجام دهد:

```bash
# فقط وقتی مدل و فضای لازم را آگاهانه انتخاب کرده‌اید
dev ai ollama pull model-name
```

هیچ model name پیش‌فرض در config pin نشده است.

## llama.cpp با GGUF موجود

```bash
dev ai llama-bench -m /models/model.gguf
dev ai llama-server \
  -m /models/model.gguf \
  --host 127.0.0.1 \
  --port 8080 \
  -c 4096
```

Benchmark را با temperature/output quality اشتباه نکنید؛ tokens/sec فقط یک بعد انتخاب model است.

## GPU چهار گیگابایت

نقطه‌ی شروع محافظه‌کارانه:

- 1B–4B parameter؛
- GGUF Q4؛
- context 2K–4K؛
- batch محدود؛
- monitor با `nvtop`/`nvitop`.

7B/8B ممکن است offload جزئی به RAM/CPU بخواهد. 14B+ هدف معمول این سخت‌افزار نیست.

## Speech

```bash
# transcription
dev ai whisper-cli -m /models/whisper.bin -f audio.wav

# Piper usage دقیق به voice model موجود وابسته است
dev ai piper --help
```

Voice/model file داخل repository نیست.

## Image

Binary `sd` از stable-diffusion.cpp Vulkan است. چون `sd` در system CLI نیز نام find/replace دارد، همیشه environment و `command -v sd` را قبل از automation بررسی کنید:

```bash
dev ai sh -lc 'command -v sd'
dev ai sd --help
```

# Local provider و gateway

Runtime محلی می‌تواند بعداً پشت 9router قرار گیرد:

```text
Neovim → 9router → Ollama/llama-server loopback
```

مزیت:

- editor endpoint عوض نمی‌شود؛
- remote/local routing در یک محل است؛
- model switch rebuild نمی‌خواهد.

اما gateway نباید service محلی را به interface عمومی bind کند. Listenerهای model و gateway برای استفاده‌ی شخصی روی loopback باقی می‌مانند مگر access control جدا طراحی شود.

بررسی listener:

```bash
lsof -nP -iTCP -sTCP:LISTEN |
  rg ':(20128|11434|8080)\b'
```

# چرا as-you-type completion وجود ندارد؟

As-you-type روی هر مکث request می‌فرستد و سه مشکل داشت:

1. overhead prompt نسبت به completion کوچک بسیار بزرگ بود؛
2. network ناپایدار typing latency را شبیه خرابی editor می‌کرد؛
3. gateway می‌توانست chat model ناسازگار را پشت endpoint FIM route کند و پاسخ خالی بدهد.

تصمیم: actionهای صریح `<leader>a`، بدون request خودکار.

شرط بازنگری در [۱۰ تصمیم‌ها](10-decisions.md) ثبت شده است.
