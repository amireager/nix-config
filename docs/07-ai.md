# ۰۷ — هوش مصنوعی

سه مخزن اینجا به هم می‌رسند. این فصل جداست چون AI فقط داخل ادیتور نیست.

| مخزن | کار | ماهیت |
| :--- | :--- | :--- |
| **nix-config** | ادیتور و کلیدهایش | |
| [aihub-env](https://github.com/amireager/aihub-env.git) | اجرای gatewayها | **daemon** — پورت می‌گیرد و می‌ماند |
| [agent-env](https://github.com/amireager/agent-env.git) | خانه‌ی sandbox برای agentها | **session** — وارد می‌شوی، بیرون می‌آیی |

**تست تشخیص: اگر به شل برمی‌گرداندت، agent است.**

---

## معماری

```
     Neovim                    agentها
  CodeCompanion              hermes, opencode
        │                     aider, gemini
        │                          │
        └────────┬─────────────────┘
                 ▼
        127.0.0.1:20128
        9router  (aihub-env)
                 │
        ┌────────┴────────┐
     Groq  Mistral  Anthropic  …
```

هم ادیتور و هم agentها به **یک** gateway حرف می‌زنند. یعنی کلیدها یک جا
تنظیم می‌شوند و همه‌جا کار می‌کنند.

---

## کلید کجاست؟ هیچ‌جا

این مهم‌ترین ویژگی امنیتی این بخش است.

کلیدهای واقعی provider در داشبورد `9router` تایپ می‌شوند و در
`aihub-env/private/` می‌مانند که هم gitignore است و هم بیرون از این مخزن.

نتیجه:

- **نه کلیدی در این کانفیگ**
- **نه کلیدی در Nix store** (که همه می‌توانند بخوانند)
- **نه کلیدی در متغیرهای محیطی**

عوض کردن مدل یا provider در داشبورد انجام می‌شود، **بدون rebuild**.

> هرگز کلید API را در کانفیگ نگذار. Nix store برای همه خواندنی است — یک
> کلید آنجا یعنی یک کلید لو رفته.

---

## راه انداختن

```sh
cd ~/dev/aihub-env && hub start 9router
```

تا این اجرا نشود، هیچ کلید AI در ادیتور کار نمی‌کند. `:AIDoctor` دقیقاً همین
را می‌گوید.

سه متغیر محیطی برای ماشین دیگر:

| متغیر | پیش‌فرض |
| :--- | :--- |
| `AI_GATEWAY` | `http://127.0.0.1:20128` |
| `AI_GATEWAY_KEY` | `local` |
| `AI_MODEL` | خالی — یعنی gateway خودش انتخاب کند |

## در ادیتور — CodeCompanion

**هیچ درخواستی موقع باز شدن nvim نمی‌رود.** اولین درخواست وقتی است که یک
کلید `<leader>a` بزنی.

**تکمیل خودکار حین تایپ عمداً وجود ندارد.** این یک تصمیم است نه کمبود —
شرحش در [۱۰ تصمیم‌ها](10-decisions.md).

### کلیدها

| کلید | حالت | کار |
| :--- | :--- | :--- |
| `<leader>aa` | `n` `v` | باز/بسته کردن چت |
| `<leader>ap` | `n` `v` | پالت اکشن‌ها |
| `<leader>as` | `v` | فرستادن انتخاب به چت باز |
| `<leader>ai` | `n` `v` | ویرایش inline |
| `<leader>ae` | `v` | توضیح کد |
| `<leader>af` | `v` | رفع مشکل |
| `<leader>at` | `v` | نوشتن تست |
| `<leader>ad` | `v` | توضیح خطاهای LSP |
| `<leader>aC` | `n` | پیام کامیت از diff |
| `<leader>ah` | `n` | تاریخچه‌ی چت‌ها |
| `<leader>ax` | `n` | نوشتن دستور برای خط `:` |
| `<leader>am` | `n` | مدل پیش‌فرض چت‌های بعدی |
| `<leader>a?` | `n` | وضعیت |
| `<leader>ag` | `n` | حالت agent — **با تأیید** |
| `:AIDoctor` | | تشخیص کامل |

پنج کلید `ae af at ad aC` پرامپت‌های **خود پلاگین‌اند**، نه چیزی که ما
نوشتیم. نوشتن نسخه‌ی خودمان یعنی یک کپی دوم از چیزی که پلاگین نگهداری
می‌کند.

### `<leader>am` در برابر `ga`

هر دو مدل عوض می‌کنند ولی نه یک چیز را:

- `ga` (داخل چت) → مدل **همان چت باز**
- `<leader>am` → پیش‌فرضی که هر چت **بعدی** با آن شروع می‌شود

وقتی یک provider شروع کرده به rate-limit کردن، دومی را می‌خواهی.

فهرست مدل‌ها از `/v1/models` می‌آید، نه از جدولی در کانفیگ. جدول نام مدل‌ها
یک کپی دوم از داشبورد است و اولین باری که provider جدیدی اضافه شود کهنه
می‌شود.

### داخل بافر چت

| کلید | کار |
| :--- | :--- |
| `?` | همه‌ی کلیدهای این بافر |
| `<CR>` | ارسال |
| `ga` | عوض کردن adapter و مدل |
| `gr` | تولید دوباره |
| `gx` | پاک کردن گفتگو |
| `gy` | کپی آخرین بلاک کد |
| `gs` | خاموش/روشن system prompt |
| `gd` | دیباگ — دقیقاً چه رفت |
| `gh` | تاریخچه |
| `gty` | حالت yolo — تأیید خودکار ابزارها (**با احتیاط**) |
| `q` | قطع درخواست |

سه کاراکتر شروع‌کننده:

```
#{buffer}   بافر فعلی را ضمیمه کن
/file       دستور — فایل، help، diff
@{agent}    ابزار — اجرای دستور، ویرایش فایل
```

### چت‌ها ذخیره می‌شوند

هر چت خودکار روی دیسک نوشته می‌شود و عنوانش را خود مدل می‌سازد.

دلیلش این خط اینترنت است: گفتگویی که وقت واقعی صرف گرفتن جوابش شده، نباید
با افتادن تونل و ری‌استارت nvim از دست برود. چت‌های قدیمی‌تر از ۹۰ روز
خودکار پاک می‌شوند.

### ⚠️ حالت agent

`@{agent}` به مدل ابزارهای `run_command`، `create_file`، `delete_file` و
`insert_edit_into_file` می‌دهد — در **پوشه‌ی کاری واقعی**، نه sandbox.

پلاگین قبل از هرکدام تأیید می‌گیرد و `<leader>ag` یک تأیید اضافه‌ی خودش
دارد، تا یادآوری کند آن prompt‌ها تشریفاتی نیستند.

**اگر کار خطرناکی داری، جایش `agent-env` است** که در یک namespace جدا اجرا
می‌شود.

### وقتی چیزی جواب نمی‌دهد

`:AIDoctor` چهار حالت را که از داخل چت شبیه هم‌اند جدا می‌کند:

```
gateway  ✖ nothing listening      → hub start 9router
models   ✖ /v1/models did not answer → پورت باز است، API نه
models   ✖ the list came back empty  → provider در داشبورد نیست
models   ✔ 7 served                  → gateway سالم، مشکل از مدل
```

بررسی بالا بودن gateway قبل از **هر** کلید انجام می‌شود و ۳ تا ۵ میلی‌ثانیه
طول می‌کشد (`/dev/tcp` با `timeout 0.5`). بدون آن، gateway خاموش یعنی یک
خطای curl از دل پلاگین، سی ثانیه بعد.

## `aihub-env` — gatewayها

daemon‌هایی که پورت می‌گیرند و می‌مانند:

| ابزار | پورت |
| :--- | :--- |
| `9router` | 20128 |
| `gpt-load` | 3001 |
| `cliproxy` | 8317 |
| `uni-api` | 8000 |
| `omniroute` | 20129 |

```sh
hub start 9router
hub stop 9router
hub list
```

چرا gateway به‌جای اتصال مستقیم:

- **یک جا برای کلیدها** — نه در کانفیگ، نه در محیط
- **fallback خودکار** — provider که rate-limit شد، بعدی
- **عوض کردن مدل بدون rebuild**
- **هم ادیتور هم agentها** از یک مسیر

## `agent-env` — agentها

session‌هایی که وارد می‌شوی و بیرون می‌آیی:

```sh
cd ~/dev/agent-env
ag -m hermes proj
```

agentهای موجود: `hermes` `opencode` `aider` `gemini` `qwen`

هر agent در یک mount namespace جدا اجرا می‌شود که `~/.ssh` و `~/.gnupg` در
آن **وجود ندارند**. همان مکانیزم `box` است →
[۰۸ سندباکس](08-sandbox.md)

دلیل واقعی‌اش هم مشاهده شد: یک agent سراغ
`~/.local/share/opencode/auth.json` می‌رفت. یعنی بدون جداسازی، هر agent
کلید agent دیگر را می‌خواند.
