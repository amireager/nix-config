# ۰۶ — ادیتور

این صفحه Neovim را بازنویسی نمی‌کند. `hjkl` و `dd` و حالت visual کار
خودشان را می‌کنند و مستنداتشان بهتر از این است.

اینجا فقط چیزهایی است که **ما اضافه کردیم**: ۳۷ پلاگین، ۲۲ ابزار زبان، و
کلیدهایی که خودمان گذاشتیم.

---

## ساختار

کانفیگ در `modules/home/dev/nvim/` است: یک `default.nix` که پلاگین‌ها و
باینری‌ها را می‌آورد، و ۱۶ فایل lua که به ترتیب مشخص بار می‌شوند.

هر فایل lua با `pcall` محافظت شده — پلاگین گمشده باعث می‌شود آن بخش کار
نکند، نه اینکه کل ادیتور بالا نیاید.

## `<leader>` کلید Space است

بزنش و صبر کن. `which-key` فهرست می‌کند چه چیزی در دسترس است. لازم نیست هیچ
کلیدی را حفظ کنی — این مهم‌ترین نکته‌ی این صفحه است.

گروه‌ها:

```
a  🤖 هوش مصنوعی      d  🐞 دیباگ           u  🎨 سوییچ های ظاهری
b  📑 بافرها           e  📁 اکسپلورر        w  🪟 پنجره ها
c  ⚡ کد و تغییرنام    f  🔍 جستجو (۲۴ کلید)  x  🚨 تشخیص ها
g   گیت              m  📝 مارک داون        r  ▶️ اجرا / REPL
l  🧠 زبان سرور        t  💻 تب و ترمینال
```

## ویژگی‌های خاص

### ادیتوری که با پروژه عوض می‌شود

`rust-analyzer` و `gopls` در ادیتور نصب نیستند. `direnv-vim` وارد عمل
می‌شود: پروژه‌ای که `.envrc` دارد باز کنی، زبان‌سرورش خودکار وصل می‌شود.

```sh
echo "use flake /etc/nixos#rust" > .envrc && direnv allow
nvim src/main.rs      # rust-analyzer آنجاست
```

بیرون از پروژه، در PATH نیست. → [۰۳ محیط‌های توسعه](03-dev.md)

### پیکرهای snacks — ۲۴ کلید زیر `<leader>f`

مهم‌ترین‌ها:

| کلید | کار |
| :--- | :--- |
| `<leader>ff` | فایل‌ها |
| `<leader>fg` | فایل‌های گیت |
| `<leader>fw` | **کلمه‌ی زیر مکان‌نما** در کل پروژه |
| `<leader>fl` | خطوط همین بافر |
| `<leader>fr` | **پیکر قبلی را ادامه بده** |
| `<leader>fu` | تاریخچه‌ی undo |
| `<leader>fk` | کلیدها — وقتی یادت نیست |
| `<leader>fp` | پروژه‌ها |
| `<leader>ft` | TODO و FIXME |

`<leader>fr` کم‌استفاده و پرارزش است: جستجویی کردی، رفتی سراغ نتیجه، حالا
می‌خواهی برگردی به همان فهرست بدون تایپ دوباره.

`<leader>fu` تاریخچه‌ی undo را **درختی** نشان می‌دهد — یعنی شاخه‌هایی که با
undo کردن و بعد تایپ کردن گم شده‌اند، هنوز قابل دسترس‌اند.

### پرش با flash

| کلید | کار |
| :--- | :--- |
| `s` | تایپ کن، برچسب بزن، بپر |
| `S` | پرش به گره‌های treesitter |
| `r` / `R` | پرش از راه دور در عملیات |

`S` تفاوت واقعی دارد: به‌جای پرش به حرف، به **ساختار** می‌پرد — یک تابع، یک
بلاک، یک رشته.

### ناوبری با treesitter

| کلید | کار |
| :--- | :--- |
| `[x` | پرش به سرِ تابعی که داخلش هستی |
| `<leader>cs` / `<leader>cS` | جابه‌جایی آرگومان با بعدی / قبلی |
| `daf` `vic` | حذف تابع / انتخاب داخل کلاس |

سربرگ چسبان (`treesitter-context`) بالای صفحه نشان می‌دهد در کدام تابع
هستی؛ `[x` می‌پرد به همان.

`<leader>cs` کاماها را خودش درست می‌کند — این کاری است که دستی انجامش
خسته‌کننده است.

### گیت

| کلید | کار |
| :--- | :--- |
| `]h` | **رابط Neogit** — کل کار گیت با کیبورد |
| `<leader>gc` | 🚀 پنجره‌ی کامیت |
| `<leader>gg` | lazygit |
| `<leader>gv` / `<leader>gV` | باز/بسته کردن Diffview |
| `<leader>gh` | تاریخچه‌ی پروژه |
| `<leader>gF` | تاریخچه‌ی همین فایل |
| `<leader>go` | باز کردن در مرورگر |

**قاعده‌ی ایموجی:** کلیدهایی که ایموجی دارند **کاری انجام می‌دهند**
(کامیت، ریست). بدون ایموجی یعنی فقط نمایش. این تفکیک عمدی است تا موقع عجله
اشتباه نزنی.

### دیباگ — ۱۹ کلید زیر `<leader>d`

| کلید | کار |
| :--- | :--- |
| `<leader>db` | نقطه‌ی توقف |
| `<leader>dB` | نقطه‌ی توقف شرطی |
| `<leader>dl` | **log point** — چاپ کن ولی توقف نکن |
| `<leader>dc` | ادامه / شروع |
| `<leader>do` `<leader>di` `<leader>dO` | over / into / out |
| `<leader>de` | ارزیابی عبارت |
| `<leader>du` | پنل‌ها |
| `<leader>dt` | تست زیر مکان‌نما (پایتون) |

`<leader>dl` جایگزین `print()` است بدون دست‌زدن به کد.

> فقط پایتون سراسری است (`debugpy`، ۲۱ مگابایت). بقیه در شل‌های خودشان‌اند
> چون `lldb` وابستگی `libclang` می‌آورد: **۸۴۹ مگابایت**.

### REPL

| کلید | کار |
| :--- | :--- |
| `<leader>rp` | IPython در tmux |
| `<leader>rc` | سلول فعلی |
| `<leader>rl` / `<leader>rs` | خط / انتخاب |
| `<leader>rf` | کل فایل |
| `[c` / `]c` | سلول قبلی / بعدی |

سلول‌های پایتون با `# %%` جدا می‌شوند — سبک نوت‌بوک، بدون نوت‌بوک.

### تشخیص خطا

`<leader>x` برای Trouble (فهرست کامل)، `<leader>l` برای LSP:

| کلید | کار |
| :--- | :--- |
| `<leader>xx` | تشخیص‌های پروژه |
| `<leader>xl` | ارجاعات LSP |
| `<leader>xt` | TODOها |
| `gd` `gr` `gI` `gy` | تعریف / ارجاع / پیاده‌سازی / نوع |

### ظاهر

| کلید | کار |
| :--- | :--- |
| `<leader>uz` | حالت Zen |
| `<leader>ul` | شماره‌ی نسبی |
| `<leader>ux` | سربرگ چسبان |
| `<leader>ud` | خاموش/روشن تشخیص‌ها |
| `<leader>fC` | تعویض تم زنده |

سه تم: `nightfox` (پیش‌فرض، پالت تیره‌ی `#0d131a`)، `catppuccin`،
`tokyonight`.

### بافر و تب

`scope.nvim` بافرها را per-tab جدا می‌کند — یعنی هر تب فقط بافرهای خودش را
در نوار بالا نشان می‌دهد. بدون آن، نوار بافر بعد از باز کردن بیست فایل
بی‌فایده می‌شود.

| کلید | کار |
| :--- | :--- |
| `Tab` / `S-Tab` | بافر بعدی / قبلی |
| `<leader>bd` / `<leader>bo` | بستن این / بقیه |
| `<leader>tn` / `<leader>tc` | تب جدید / بستن |

## نکته‌های ریز که وقت می‌گیرند تا پیدا شوند

- **`q` پنجره را می‌بندد** — در پنجره‌های کمکی و لیست‌ها
- **`<Esc>` هایلایت جستجو را پاک می‌کند**
- **`Space` در حالت insert** از insert بیرون می‌آید
- **`j`/`k` روی خط بصری حرکت می‌کنند** — در متن wrap شده مهم است
- **`H`/`L`** بالا و پایین صفحه
- **`<C-Left>`/`<C-Right>`** اندازه‌ی پنجره
- **`guess-indent`** تورفتگی فایل را از خودش می‌فهمد، بدون کانفیگ
